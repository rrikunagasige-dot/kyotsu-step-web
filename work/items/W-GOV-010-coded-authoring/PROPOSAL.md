# 提案書 — 教材制作の判断と機械処理を分離する

Work: W-GOV-010
Proposal: P-001
Date: 2026-10-23 JST
Status: PROPOSED（仕組み・教材とも未変更）

## 1. 目的と今回の停止範囲

毎回AIがルールを思い出して自由に教材を設計し、完成後に同じAIが見直す方式への依存を減らす。承認済みの教材形式・教育上のパターン・検査条件を、版管理されたデータとコードとして再利用する。AIは、機械で確定できない意味の判断と、適用範囲が明示された設計を担当する。

ユーザーの「先に待つ」に従い、W-MATH-027の教材修正は保留する。構成修正P-001への承認はまだなく、この提案の作成を教材修正の承認として扱わない。今回行うのは新しい仕組みの提案までで、公開版・憲法・指示辞書・Work OSを変更しない。

対象は、まず数学の教科書／学習モード。数学の練習モードも設計上は別の型として扱うが、別チャット担当分を変更しない。物理等への適用は、各モードの正本を照合した後の別範囲とする。

## 2. 問題の捉え方

今回の失敗には、別の原因が混ざっている。

1. 見出しは3つと決まっていたのに4つに増えた。これは記憶や文章センスに任せる必要のない、機械で拒否できる仕様違反。
2. 計算途中を飛ばし、一つの選択肢で複数の操作を済ませた。承認済みの導出パターンと、表示する途中式が結び付いていなかった。
3. 図の目的・読み方や、前後の説明のつながりが弱かった。必要要素の欠落は構造検査できるが、説明内容の適切さは意味の審査が必要。
4. 数学的正答・クリック・画面幅が合格だったことを、教材としての合格にまで広げた。保証できる範囲を分ける必要がある。

したがって「AIにもっと注意させる」だけでなく、仕様違反が制作工程を通れないようにする。ただし、コード自身の誤りや、型の選び間違いもあり得る。期待される改善は、同じ評価事例で実測し、未測定の削減率は言わない。

## 3. 担当を分ける

| 作業 | コードへ任せる部分 | AI／人が担う部分 |
|---|---|---|
| 正本・規則の選択 | 対象モード、正本版、承認済み規則の読込と一致確認 | 不明な出典、矛盾した指示、適用範囲の解決 |
| 原資料の取込 | 文・式・図・問題番号の抽出、出所の記録 | 読取誤り、曖昧な数式、図の意味の確認 |
| 章の構成 | 固定した3テーマ、所属、順序、欠落・重複の検査 | 最初に決めるテーマと概念間の関係 |
| 完全な解法 | 適用可能な既存手順の展開、算術・条件付き数式変形の検算 | 使う方針、必要な仮定、未対応の証明・解法 |
| 穴 | 承認済み設計から指定された式の部分を穴へ変換 | 何を考えさせるか、どこまで支援するか |
| 選択肢 | 指定された誤り操作から候補を生成し、既知の条件下で正誤・重複を検査 | 誤答が学習上意味を持つか、何を診断するか |
| 本文・図 | 必須接続要素、参照先、表示順、回答前後の解放条件の検査 | 自然な文章、図を使う必然性、理解しやすい説明 |
| アプリ化 | 承認済みデータの変換、UIの組立、進捗・履歴・表示の処理 | 新しい表現や操作が必要な場合の設計 |
| 受入 | 機械検査の実行と証拠保存 | 意味の審査、ユーザーの細部確認と全体総チェック |

初めて出会う問題の方針まで無条件に機械化するのではなく、型に合う部分を確定処理に移す。未対応・不明・検算不能は、AIの判断対象として明示する。

## 4. 固定するものを四種類に分ける

### A. 教材の型

教科書／学習と練習を別の型にする。

- 教科書／学習：具体的な導入→必要な知識→一段ずつの導出と判断→意味の整理→概念・性質→必要な証明→使用と再使用。概念によって順序を選ぶが、選んだ型の必要要素を欠落させない。
- 練習：元問題を独立に保持→完全解法→問題内／問題間の依存→支援付きの操作→元問題への最終回答。教科書の会話や概念導入を機械的に移植しない。

既存の正本と承認例から必要要素を取り出し、最初に型を承認する。以後は内容を入れるために型を毎回書き直さない。型で表せない教材には、欠落を無視した自由生成ではなく、拡張案を用意する。

### B. 指導のパターン

例：多項式の加減、分配と同類項整理、平方公式の導出・適用、共通因数、置換、平方根の符号確認、負数による不等号反転、絶対値の二枝。

各パターンには、次を持たせる。

- 適用できる条件と使えない条件
- 必要な既習知識・変数・定義域
- 完全な式の変形列と各行の理由
- 学習者が行う判断／計算と、その前に見える根拠
- 表示する途中式、穴にできる部分、回答後に見せる部分
- 図の役割、文章でつなぐ箇所
- 誤り方、検算方法、適切な例と不適切な例
- 承認元・版・対象モード・検査例

単なる似た文章の集まりではなく、条件と手順が検査できるパターンにする。

### C. 禁止条件・必須条件

例：3テーマ以外の同格カード禁止、原問欠落禁止、未定義変数禁止、必要な途中式の後出し禁止、未回答の答えの先出し禁止、異なる二問の解を一つの選択肢へ束ねない、正答後の式を壊さない。

規則ごとに適用範囲を持たせる。「大見出し3つ」を全ての小見出しへ適用したり、「一つの判断」を自然な係数・次数の組まで機械的に分断したりしない。数・条件・必須辺を検査するコードと、教育的妥当性を審査する項目を分ける。

### D. 承認事例と却下事例

承認済み教材を全て無条件の正例にしない。今回のように後で欠陥が分かった場合、影響するブロックの正例ラベルを取り消す。画像だけでなく、原問題、完全解法、型、穴、表示順、ユーザー評価、その評価が有効な版を保存する。

却下事例も、何が失敗したかを付けて残す。新しい教材が似た失敗を含まないか、自動検査と意味の審査の両方に使う。

## 5. 穴をキーワードだけで決めない

キーワードは候補を見つける補助にはできる。しかし「係数という語があるので次の数を消す」「答えの文字列を全て四角へ置換する」では、同じ数の別の出現まで消したり、考える対象を誤ったりする。

穴は、数式の構造の特定箇所と学習行為に結び付ける。

例：(3x+1)(x+2)を展開する場合。

1. 使う関係は分配法則。
2. 四つの積を作る。
3. 3x×2、1×xをそれぞれ計算する。
4. 同類項6x+xをまとめる。
5. 3x²+7x+2へ組み立てる。

数式データの「3x×2の結果」に穴のIDを付け、その答えが6xで、学習行為が積の計算であると指定する。表示文章中の「6」へ穴を付けるのではない。どの行を表示し、どの行を穴にするかは、承認された型と当該問題の設計データで決める。毎回全ての算術を穴にはしない。

AIは、この設計データと本文を作る。コードは設計データから穴を作り、原式と完成式を照合する。データに「一段」と書いてあるだけで合格とはせず、指定パターンの式の変形と学習行為が一致するか検査する。

## 6. 改訂する制作手順

既存の提案承認と三つの確認ゲートは維持し、その内側の実行を次の形へ変える。

| 段階 | 処理 | 次へ渡すもの |
|---|---|---|
| ① 正本・条件の固定 | コードが対象モードの型・規則・承認版を読み込む。AIは曖昧な所だけ解決 | 原資料対応表、使用する型と規則の版 |
| ② 構造の取込 | 文・式・図・番号を抽出。読取誤り・不足を確認 | 出所が追える問題・図・数式データ |
| ③ 型の候補提示 | 登録パターンを条件から絞る。AIが適合性と未対応部分を審査 | 採用パターンと、その理由／適用条件 |
| ④ 完全解法の用意 | 対応済みパターンはコードで展開。未対応はAIが完全解法を作り、数式・条件を検算 | 途中式・理由・依存を持つ完全解法 |
| ⑤ 教材設計 | AIが必要な本文、図の読み方、穴と支援の程度を構造化して提案 | 具体的な修正／作成案。未承認のまま生成へ渡さない |
| ⑥ 確定的な変換 | 承認済み設計をコードで教材データ・UIへ変換。変換器は内容を創作しない | 再生成可能な教材、使用規則一覧 |
| ⑦ 検査と意味の審査 | コードが検査し、AIは文章・根拠・型の誤用・未対応部分を審査 | PASS／FAIL／UNVERIFIEDと具体的な根拠 |
| ⑧ 既存の受入 | Gate①実画像、Gate②横断監査、Gate③固定版の実アプリ通し確認 | ユーザー受入と履歴 |

仕様に合わない出力を自動で捨てたり、問題を抜いたり、勝手に簡単な別問題へ置き換えたりしない。失敗箇所を残し、同じ承認範囲の機械的な修復だけを再試行する。意味・方針・支援の変更が必要なら修正案へ戻す。

## 7. 検査の保証範囲

| 検査対象 | 初期段階で実行できること | それだけでは保証できないこと |
|---|---|---|
| 構成 | 大見出し数、所属重複、原問対応、導線、集計 | まとまりの選び方が学習者に自然か |
| 導出 | 登録パターンの必要行・理由・依存、既知の変形の妥当性 | 任意の証明の完全性、未知の方法の指導難度 |
| 穴 | 対象の型、数式位置、正答、必要根拠の表示、回答後の解放順 | その穴に十分な学習価値があるか |
| 答え漏れ | 依存する後続ブロックの先出し、既知の答え表現の露出 | 自然文の言い換えや図から実質的に答えが分かる全ケース |
| 数学 | 算術、対応範囲の恒等式、定義域・符号、特定の同値判定 | 一般の数式同値性。判定不能は未確認とする |
| 選択肢 | 重複、検算可能な誤答、指定した誤り操作との対応 | 誤答のもっともらしさ、教育的意味 |
| 図と文章 | 参照の順序、読み方等の必須欄、表の値と式の対応 | 必須欄の文章が実際に明快か |
| 画面と履歴 | 表示状態ごとの寸法、式と文字の結合、保存・復元、旧履歴保持 | 初学者がつまずかず読み進められるか |

「説明欄が存在する」ことと「説明が分かりやすい」ことを分ける。検査対象外を明記し、機械合格を教材全体の合格へ拡大しない。検査器と生成器が同じ答えを写して一致するだけの試験にもさせない。

## 8. 学習・フィッティングの扱い

パターンの蓄積には価値があるが、初めから大規模なモデル学習を始める必要はない。

第一段階は、承認・却下事例を構造化し、人が読める規則とパターンの候補検索を作る。規則で確定しない部分を蓄積した後、パターン選択、穴の候補順位、文章の問題箇所の検出などに学習を使えるか評価する。

学習用と評価用は原問・同型問題の系列で分け、同じ教材の言い換えだけを別評価として数えない。ユーザー承認は「その版のその範囲」のラベルであり、学習効果の実証と同一ではない。

モデルの提案は明示的な仕様・数学的条件・ユーザー承認を上書きしない。高い予測スコアを自動公開の許可にしない。外部への教材送信、有料学習、モデル追加契約はこの初期提案の実装範囲に含めない。

## 9. 導入順と初期成果物

### 第1段階：既存ルールと事例を整理

既存教訓を「機械で確定可能」「構造化データがあれば検査可能」「意味の審査が必要」に分類する。教科書／学習と練習それぞれの型を定義し、どの既存承認が根拠か対応させる。現行の憲法や正本を重複した別ルールで置き換えない。

成果物：規則対応表、二つのモードの型、パターン仕様、適合例と不適合例、検査の保証範囲。

### 第2段階：狭い範囲で試作

数学・学習モードの次の三つを先に扱う。

1. 章入口の3テーマと所属・導線・集計。
2. 分配→積の計算→同類項整理（今回の画像②・③・⑤・⑦に関係）。
3. 図の表→一つの積→四つの積→式、という対応（画像④に関係）。

既存の問題と図を使い、公開教材へ自動反映しない。型に合わない原資料も必ず試し、未対応として止まることを確認する。使う解法・数値・問題設定は原資料に忠実であることを別に検査する。

成果物：構造化データ、変換器、検査器、実教材との差分、対象SHAの確認画像、機械検査と意味の審査を分けた報告。

### 第3段階：同じ事例で比較

最初の評価群は30事例を目安とする。今回の却下10事例、局所的な適切さを再確認した承認10事例、試作に使わない別事例10件。見出しの不具合等は問題数と区別して一つの事例と数える。対象範囲に適用できない項目は理由付きで除外し、合格数へ足さない。

見逃した欠陥、誤った警告、未対応の割合、意味の修正回数、制作・確認の負担を、従来方式と同じ原資料で比べる。既知の10失敗が検出できることは回帰対策であり、未知の失敗にも強いことの証明ではない。未使用の評価事例についても結果を別に報告する。

### 第4段階：採用判断と修正再開

改善が確認できた規則・パターンだけを既存作業手順へ組み込む。W-MATH-027の3テーマ復元と本文修正を、その仕組みで再設計・提示する。未対応の部分はAIが担当し、検査対象として残す。新しいパターンが必要になれば、適用条件と事例を追加して版を上げる。

初期評価後に、数学の練習モードも同じ考え方で別途試す。教材の型は別、出所・数式・履歴・画面の共通処理は共有できるようにする。

## 10. 採用前に満たす条件

- 既存の提案承認、修正優先、Gate①〜③、公開権限の区別を保持する。新しいユーザー確認ゲートは増やさない。
- 見出し数等の明確な違反が、AIの注意力に依存せず検出される。
- 今回の途中式省略・複合選択肢・図の説明不足を、対応する型の不足または意味の審査項目として記録できる。
- 型の自己申告だけで合格にならず、実際の変形列・表示順と照合する。
- 未対応・読取不能・検算不能はUNVERIFIEDとして残り、問題を落として成功扱いにしない。
- 原問・原図・正答・出典対応・旧履歴を保ち、既存の適切なブロックを壊さない。
- 同じ入力と同じ版の規則・承認済み設計から、同じ教材データを再生成できる。AIによる自由生成の部分まで完全に同じになると主張しない。
- ユーザーが文章・実画像・実アプリを確認する現行の受入を代替しない。
- 評価結果と残る見逃しを報告し、測っていない改善率を宣言しない。

## 11. 変更する文書・コードの案

採用時は、既存のgovernance/WORK_SYSTEM.md、モード別正本への参照、教材データと検査コードに、機械処理と意味の審査の契約を追加する。最終的な保存場所・スキーマは、既存コードとの適合を調べて決める。

必要な要素は、モード別の型、パターンと規則の登録データ、出所付き中間データ、数式／順序／網羅性の検査、変換器、独立した評価事例、生成物の版とSHAの記録。

憲法の既存原則は今回の案を支えられる。まず通常Workの改訂案として進め、原則の意味を変える必要が確認された場合だけ別の憲法改訂案を出す。今回の提案段階で憲法・指示辞書を変更しない。

## 12. 今回の承認対象

初期導入の第1〜第3段階（ルール・型の整理、狭い試作、比較評価）を進める案である。本番教材の自動書換え、公開、全モードへの一括適用、大規模学習は含まない。

まず仕組みがどこまで誤りを防げるかを実例で検証し、その報告に基づいて、正式な運用変更と教材修正の再開を判断する。
