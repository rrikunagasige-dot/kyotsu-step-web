## 0. 目標と承認範囲

目標は、AIが設計と全文を作りコードが最後に検査する制作から、**コードも解法・教える順序・説明骨格・穴・誤答・図表の候補を作り、AIが文脈と教育上の適切さを判断し、異なる根拠で双方を検証する制作**へ改めること。

今回の依頼は、この工程と実現方法を具体化した詳細提案の作成。ユーザーの方向性への賛同を、まだ提示していない本P-002の実装承認へ読み替えない。

| 区分 | 内容 |
|---|---|
| 確定済み | 第一タイトルN01–N06/NE01の正式受入、公開ソース22bc43ba。完成単位を既存公開アプリで確認する方式。旧画像票の承認待ちは廃止 |
| P-002で承認対象とする実装 | 数学・教科書モード限定の制作規則、原資料処理、候補生成、AI契約、compiler、検証・再開・公開経路の共通化。第二タイトル全件の棚卸しとN07全件の具体設計準備 |

## 4. 正本データと成果物の接続

数学の値を本文・図・rendererへ別々に手入力しない。責務別のデータをID/hashで結ぶ。

| データ | 正本の内容 | 派生物・検証 |
|---|---|---|
| source manifest/blocks | 原資料の位置・内容・構造・原図hash | SOURCE_MAP。抽出を新事実の根拠にしない |
| problem contract | 求める対象、範囲、条件、最小・全部・既約等の答え方 | 解法・正答判定・選択肢の共通入力 |
| solution trace | 操作の入力・規則・条件・出力・根拠 | 教師用完全解法、数学検査、設計候補 |
| lesson plan | 採用順、既習、穴、本文、図表、解放条件 | runtime、提案書、coverage、QA対象 |
| render plan | 論理行、整列群、番号anchor、画面役割 | 幅別表示。数学の結論を変えない |
| audit findings | 該当ID、根拠、深刻度、戻り先、解決状態 | 修正と回帰例。自己採点だけにしない |
| build/release record | source、plan/compiler/renderer hash、成果物と環境 | 公開照合・再現・復旧 |

対応範囲の数式は構造を持つ式として扱いLaTeXを生成する。元OMML・原式LaTeXも保持し、CASで勝手に簡約してから保存しない。定義域・適用条件・解集合と、表示文字列を分ける。詳細な型・ファイル・コマンドは技術設計付録に定める。

## 5. 原資料取り込みで防ぐこと

1. Wordの段落・表・OMML・画像relationshipを順序付きで読む。分母、根号対象、指数、循環記号を平文から推測しない。
2. 元番号はsource IDとして保持。一原問を複数ノードにできるが、source番号と教材ノード番号を混同しない。
3. 無番号の定義・性質・例・証明接続にも安定IDを付ける。採用先／別単元参照／省略候補と理由を全件記録する。
4. 原図・式・本文の不一致は両方を残して未解決とする。既存アプリの答えから原本を逆算して確定しない。
5. 未対応抽出は位置と原本参照を残し、網羅率の分母から除いて100%にしない。
6. 抽出欠損と編集上の省略は別に扱い、前者は抽出、後者は設計へ戻す。

原本や非公開原文を新しくpublic repoへコピーする工程にはしない。追跡用ID/hashと許された教材・自作設計の範囲で運用する。

## 6. 解法を作るコード

規則は文章テンプレートに加えて、適用条件・計算手順・出力構造を持つ。

| 規則群 | 生成するもの | 条件・検査 |
|---|---|---|
| 分数→小数 | 整数部分、商・余り、終了または循環開始・周期 | 分母非零、符号、正の分母へ正規化。整数演算 |
| 循環小数→分数 | 周期位置、倍率、二式、差、両辺の除算、約分 | 最短周期、純循環と混循環の区別 |
| 有限小数の分母 | 既約化、分母の2・5因子、10の累乗へそろえる構成 | 既約分母を調べる。分母1・符号も扱う |
| 有限範囲の列挙 | 全候補と除外理由 | 指定範囲全走査、漏れ・重複検査 |
| 数の分類・閉性 | 定義照合、反例、包含・操作条件 | 自然数の約束、除数非零、例と一般論の区別 |
| 絶対値 | 位置・距離、符号別分岐、0 | 場合の網羅性・境界。N08以降 |
| 平方根 | 平方一致、主平方根の非負、全平方根との区別 | 実数条件、√(a²)=|a|、0。N09以降 |
| 根号計算・有理化 | 因数分解、適用条件、分子分母への同一因子 | 分母非零、積と和、元の正条件。N10以降 |
| 二重根号 | 和積条件、交差項、候補、平方一致、符号 | 平方が同じだけで符号確定しない。NE02段階 |

後半の規則をN07のために全て先行実装しない。最終値だけをCASで得て説明を後付けせず、各操作のtraceから本文・穴・図を生成する。simplify成功は教える順序の合格ではない。

N07の余り遷移は、非負余りrと正の分母qについて10r=q×次の桁+次の余りで生成。余り0で終了、既出余りで循環を検出。有限例の実行と「余りの種類が有限」という一般論証を別に保持する。

循環の最小倍率は、書かれた繰返し文字列の長さを無条件に使わない。「6969」は最短周期「69」へ正規化できる。混循環なら非循環部も記録し、純循環規則を誤適用しない。0の循環・9の循環による表示の非一意性も入力処理で明示する。原問にない一般例を教材へ追加する意味ではない。

## 7. 教える順序の候補生成

**依存グラフだけでは教える順序にならない。** P-001の「コードは順序を検査するだけ」を変更し、意味付き段階規則から候補を作る。

1. 最終要求と結論を固定し、必要な中間結果をたどる。
2. 解法規則の段階を展開。全計算を同じ細かさにはしない。
3. 未導入の定義・記号・性質を、初めて使う前へ補う候補を作る。
4. 複数の非自明判断は分割候補を作る。非自明性は既習台帳と規則で明示し、式の長さだけで決めない。
5. 部分計算を結果利用までつなぎ、無用なA→B→A往復を除く。
6. 結果を使える形にまとめ、元の問題へ戻し意味を確認する位置を付ける。
7. 条件を満たす候補をAIが採用・修正・却下し理由を残す。

| コードの必須条件 | AIの観点 |
|---|---|
| 未導入前提、未来結果、別例の結果混入がない | その途中式を求める必要性が伝わるか |
| 操作入力が前段出力と対応する | 方法を選ぶ着眼があるか |
| 部分結果に用途があり、独立概念説明は役割がある | 細分化しすぎて全体を見失わないか |
| 条件分岐を無条件手順へ潰さない | 例・比較・証明の順序が適切か |

候補の優先順位には未説明の飛躍、同時に要求する新判断、無用な往復、保持する未確定情報を使う。これらは設計指標であり学習効果の証明ではない。最短行数・文字数を目的にしない。採用順はorderedNodeIdsとして保存しrendererで変えない。

## 8. 小中高の説明方法を文章生成へ落とす

学年名だけで一つの型を割り当てない。具体物・数量関係・文字式・条件付き論証という表現の違いと、読者の既習に応じた型を持つ。

| 原則 | コードの項目・生成 | AIの確認 |
|---|---|---|
| 問題と解答過程を区別 | 問題・条件・方針・導出・結論の役割 | 途中で別の問題が始まったように見えないか |
| 数量の意味を式へ結ぶ | 対象・数量・対応・単位の参照 | 初めて文字に置く意味が分かるか |
| 操作対象を書く | 対象・共通部分・変えない部分から誘導文 | 「これ」「それ」が曖昧でないか |
| 根拠を示す | 定義・性質・条件を参照 | 文型だけ揃い根拠が空でないか |
| 結果を問題へ戻す | resultとgoalから結論骨格 | 計算だけで要求への回答を忘れていないか |
| 式・図・言葉を対応 | 同じsource/value IDを参照 | 図のどこ・式の何を見るか伝わるか |

文章型は、必要性、操作対象、条件確認、計算後の意味、前結果利用、場合分けを用意。全段階へ同じ「まず〜次に〜」を強制しない。

例えば一次項の整理では、コードが「対象2xy−3x／共通因数x／残る係数2yと−3／次に係数を読む」を持ち、説明骨格と式を生成。AIが前後を見て本文にする。未知の操作を「整理すると」で隠さない。

本文中の数学は参照部品で生成。AIが自由文に具体式を追加したらclaimへ登録し正本と照合する。ただし自由文の意味を完全機械判定できるとはしない。接続語や項目の有無だけで文章合格にしない。

誘導本文は対象と着眼を示す文章を中心にする。答える問いは操作部品へ置けるが、本文を問句の列にしない。会話は迷い・着眼に必要な箇所のみ。三人全員を毎回登場させない。

## 9. 穴を思考の役割で提案する

Masterの8分類を維持し、計算・符号判断等は操作の下位属性として持つ。

| 穴の分類 | 提案条件 | 避けるもの |
|---|---|---|
| 問題理解 | 条件・範囲・対象の読分け | 無目的な転記 |
| 復習 | 今必要な既習知識 | 未導入名称・定理の当て物 |
| 状態更新 | 操作後の値・余り・範囲の更新 | 元と更新後の混同 |
| 方針選択 | 次操作の選択が必要 | 直前で操作を言い切る |
| 式・表現生成 | 係数の括弧、倍率後の式、分数構成 | 最終数値だけ空け構成を代行 |
| 導出 | 中間の数学的結合を作れる | 複数未習判断を長い一候補へ束ねる |
| 理由 | 条件・性質を根拠に使う | 正解の言換えだけ |
| 意味・解釈 | 結果を元概念へ戻す | 計算終了で途切れる |

穴候補は、対象操作、前提、空ける範囲、理由、先に見せる支援、正答後説明を持つ。採否と理由を保存し全候補を穴にしない。

原問ごとの主要判断に「本人が担う／見本として教える／既習として参照」を対応させる。本人が担う主要判断が0なら理由を必ず監査する。計算穴だけ増やす案を検出するが、穴数や割合を機械的な合格条件にしない。

スマホで長い筆算を暗黙に要求しない。対象を表示し意味ある途中操作へ分ける。支援を減らす根拠は、方法を先に説明・練習した事実。正答履歴だけで習熟を断定する適応学習は今回導入しない。

## 10. 選択肢・ヒント・誤答説明

誤答は数字を変えるだけで作らず、符号脱落、倍率と周期の混同、分子分母逆転、片側だけの除算、片側だけの約分など操作に対応する誤り規則から候補を作る。

各候補に、数学的真偽／問題条件への適合／見た目の区別／誤り理由を検査。等式は正しくても「最小」に合わない場合はその理由を説明し、「誤答」と「数学的に偽」を混同しない。

同値な正解、条件次第で正しい候補、表示だけ異なる重複は除くか問いを修正。十分な候補が作れなければ既存schema内で問いを再設計し、四択を埋めるため不自然な式を出さない。回答形式変更は具体設計に明記する。

段階的ヒントは既存の承認方針を維持。着目→既知性質→操作の絞込み→回答後説明を区別。最終支援で解答開示するなら方針と状態を明示し、初期本文・早期ヒントに無自覚に答えを置かない。

誤答後は取り違えた点を示し同じ問いへ戻す。正答後も説明を読めるようにし、自動的に先へ飛ばさない。一候補一カード、集合と同じ本物の操作部品を使い、四角の文字とボタンを重ねない。

## 11. 図表も生成・検証する

| 関係 | コードの候補 | AIの判断・検査 |
|---|---|---|
| 位ごとの商・余り | 位／割る前の値／商／余りの追跡表 | 桁との対応、未回答セルの露出 |
| 二式の対応 | 整数部分・循環部分をそろえる縦配置 | 引く対象が見えるか。色だけに依存しない |
| 数の分類 | 定義・包含の表、必要なら包含図 | 具体例と集合全体を混同しない |
| 位置・距離・符号 | 原点・点・距離を持つ数直線 | N08-F01保持、初期と正答後の意味 |
| 平方根・整数部分 | 数直線上の範囲・基準点 | N09-F01の値・向き・境界 |

目的、読み取る関係、利用する式・判断、表示時点、値の参照を必須にする。目的のない図を追加しない。原図は保持し、新作図は必要性を設計してから作る。

正確な数学図表はSVG/HTML等を基本にし、描画器へ別の正解値を固定入力しない。図の説明文・altも早期解答を検査。画像を縮めるだけで狭幅対応とせず、ラベルの可読性を実画面で確認する。

## 12. 長さを扱う画面と本文の関係

段階分けと本文削除は別。全文は保持し、今の目標・必要な前結果・今答える操作に焦点を合わせる。

| 領域 | 内容 | 決定方法 |
|---|---|---|
| 問題 | 元の問い・条件・答え方 | problem contract参照。導出と役割を区別 |
| 今の目標 | 一段の小目標 | teaching node。大見出しの重複を避ける |
| 使う条件・前結果 | 今必要な確定済み結果 | knownRefsと解放条件。次の答えは出さない |
| 誘導・式・穴 | 着眼の本文と一段の数学 | 採用planどおりの順序 |
| 回答後 | 根拠・意味・結論・次の用途 | 正答後に解放。本人が読んで進む |
| 完了段階 | 保持する結論と全文への入口 | 要約でも結論を残し、詳細を展開可能 |

境界は再利用できる結果や一つの概念理解が成立する所。文字数・画面高で意味を切らない。長すぎたら設計へ戻し、CSSで説明を隠して解決しない。

概念本文は黒字を基本にし、色は操作・状態・フィードバックへ使う。問題・例題・性質・証明を見分けられる役割表示とし、大見出しを乱立しない。集合と第一タイトルの受入構造を基準にしつつ、多項式固有の見せ方を実数へ転写しない。

## 13. 数式の整列・番号・余白

既存TypesetFormula/typesetRows/NumberedEquationを維持し、論理構造を渡す。

- 一つの式の継続と等式変形の次行を区別。改行しただけで等号を追加しない。
- 短い等式は一行。同じ変形群は等号位置をそろえ、群全体を本文幅内へ配置。
- 項・因子・根号・分数・指数・符号を保つ境界で折返し、候補内部も検査。
- 論理式IDに番号を結び、物理行数やDOM順で採番しない。前結果・履歴でも番号を保持。
- 番号が式幅を過剰に奪わず、重なる時だけ右下行へ移す。正答前後を測る。
- 段落・式・外枠の余白を足し重ねず、所有者を一つにする。
- parse・幅だけでなくMathMLの分母・分子・根号の対象を照合。

package.jsonはKaTeX ^0.16.22を指定。Web最新版の機能を現行にあると仮定せずlockfile解決版で検証する。MathJaxは設計参照であり、renderer交換・依存更新を前提にしない。N02固有比較adapterは再現用に保持し、第二タイトルの数学値をrendererへ新規固定入力しない。

## 16. コードとAIによる二つの検証

同じ誤抽出や正解値を双方が使えば両方誤る。経路と限界を分ける。

| 対象 | コードの根拠 | AIの根拠 | 限界 |
|---|---|---|---|
| 原資料 | 元構造・対応・画像hash | 原資料と段落の読直し | 抽出不能部は原本確認 |
| 数学 | 規則条件、正確な計算、固定例、別方式 | 原問からの別解・論理検証 | サンプルは一般証明ではない |
| 順序 | 前提・操作・再利用・分岐制約 | 初学者に見える情報だけで読む | 自然な理解を形式検査だけでは保証不可 |
| 穴 | 操作対応、既習、露出、正解重複 | 転記・当て物・思考代行を探す | 説明済みと理解済みは別 |
| 文章 | 数学claimと用語・参照の整合 | 接続・必要性・説明の十分さ | 自由文は完全自動検証不可 |
| 画面 | 実境界、操作、MathML、保存状態 | 実画面の読みやすさ | ピクセル一致は教育的合格ではない |

監査AIへ原資料・契約・実教材・適用基準を渡し、制作AIの自己評価を合格根拠にしない。指摘は位置・根拠・反例・戻り先を持つ。別役名・別セッションだけで独立性が成立したとは書かない。

同じplanから出すcoverageや操作一覧は整合性検査。正当性の独立証拠には原問固定例、受入版、拒否例、別方式検算を用いる。

## 17. 検査の通過・保留・故障注入

PASS/FAIL/UNVERIFIED/UNSUPPORTED/NOT-APPLICABLEを区別し範囲と理由を記録。必要検査の未実行・0件をPASSにしない。対応外でも同じ主張に有効な別根拠があれば明記して扱える。根拠が残らなければ公開を止める。

| 検査群 | 通過条件 |
|---|---|
| 原資料 | 全原問・重要無番号説明・原図に対応。省略理由・条件が確認済み |
| 数学 | 正答・中間操作・誤答・条件・要求形式に有効な根拠。例だけで一般主張を合格にしない |
| 教材 | 既習→小目標→操作→結果→用途が接続。重要な推導を全代行しない |
| 状態・露出 | 通常・ヒント・誤答後・正答後・前結果・履歴・図説明が設計どおり |
| 実操作 | 全回答到達、誤答→ヒント→再回答、保存・再読込・履歴・戻る・reset |
| 数式・画面 | 全式・全候補に欠損・意味変化がなく、番号・操作を含め幅内 |
| 保護・回帰 | 範囲外データ保持。共有変更は受入基準と比較 |
| 公開 | 検査ソース・build成果物・公開実物の対応。旧版・空routeを新教材としない |

検査器自体を試す固定故障例：未来結果参照、分母0、平方根の負号違反、最小条件違反、分母が集合へ変化、穴直前の答え、候補内だけのoverflow、別例のx、指定N0件、古いSHAのPASS再利用。実装を写すだけの試験を増やさない。

画面は320/360/390/1440pxを基本に、正答前後・候補・誤答支援・前結果・全履歴展開。フォント確定後に測る。幅だけで読みやすさを保証せずAIも実画面を確認。未検証端末まで保証しない。

## 19. 安定ID・旧回答・改訂

| 変更 | 進捗 |

| 思考操作追加 | 新IDは未回答。旧回答で追加導出まで完了にしない |

## 20. 実行・中断・再開

各jobにunit、原資料hash、規則版、plan hash、AI指示版・モデル設定、環境、入出力hash、状態、次工程を記録。AIの設定を保存しても再生成の一致は保証しないため採用出力を保存。compilerは同じ入力から同じ出力を保証する。

出力は一時領域で検証後に確定し、不完全JSONをruntimeへ取り込まない。依存未確定の後工程へ進まない。同じ失敗の無限再試行を避け、初期案は一工程あたり自動修正2回まで。その後は原因と次案を整理する。品質条件を緩める値ではなく実測で調整する運用値。通常の一意な修正で確認を増やさない。

確定入力の独立検査・別出力は並行可能。plan同時上書き、移行と公開競合は不可。AI役割は工程を分ければ実施でき、複数agentの自動起動を前提にしない。

## 21. 変更時の証拠失効と再検査

| 起点 | 失効するもの | 保持できるもの |
|---|---|---|
| 原資料・条件 | 対応解法以降と利用先 | 無関係な問題 |
| 数学規則 | 使用する解法・穴・説明・図・検査 | 未使用単元。共有影響の確認は必要 |
| 順序・穴・解放 | 本文接続・状態・露出・操作・移行検査 | 条件不変なら完全解法の数学証拠 |
| 文章 | claim・用語・露出・読解・画面 | 数学不変なら計算証拠。条件文変更は数学も再検査 |
| 図表 | 値対応・解放・画面・説明文 | 無関係な図・問題 |
| renderer/CSS/fonts | 意味構造・候補・履歴・共有対象 | 数学データ不変なら解法証拠 |
| compiler/schema | 生成差分・利用plan構造・関連動作 | 内容不変の正本解法 |

再利用証拠は元hashと再利用理由を残し、新SHAで全再実行PASSと付け替えない。基準画像は受入版22bc43ba等から作り、候補を自動的に新基準へ昇格しない。

## 22. compile・公開・ユーザー確認

承認済みNの実装→内部検査→source凍結→build→同成果物検査→既存Pages公開→実物照合→直接URLを基本とする。

1. HEADと実ファイル・plan/compiler設定・保護hashを照合。reset--mixedだけで実体切替済みとしない。
2. lockfileと環境を固定。同じ成果物を検査・公開する。既存経路で再buildが残れば同一性を検証し、同一成果物と偽らない。
3. source SHAとplan/規則/生成器版をmanifestへ。配信資産hashも照合。manifest自身のhashを自身へ入れる循環は避け、最終artifact hashは外部release recordに置く。
4. hosting main更新直前にlive HEADを再確認し、期待HEAD付き更新と公開直列化で競合を防ぐ。別作業をforce上書きしない。
5. 公開後にmanifest・資産・対象route・全対象操作を照合。HTTP200だけでは空画面・旧版を検出できない。
6. ?v=はcache対策で版固定機構ではない。実配信sourceを証拠にし、後日同URLが旧版を表示するとは約束しない。
7. 公開前FAILなら未公開。公開後重大破損は証拠を残し前版復旧または局所修正。復旧時も進捗を確認。

完成NごとにURLを渡す。N07の既存routeはmath-numbers-expressions-n07だが、実公開・照合前に新N07完成URLとは案内しない。今回の提案作成では公開版を変更しない。

## 23. ユーザー指摘を規則・評価例へ戻す

版・N・問題・表示状態・期待との差・原因工程・影響範囲を記録。ユーザーに内部ID探しを強制せず、こちらで画面と対応させる。修正は単元固有と共通化可能部分を分ける。

例えば一次項→二次項→三次項は具体例の手順であり、循環小数へ移す共通規則ではない。「対象部分を一つずつ完了し最後に全体へ戻す」が移せる原則。

再利用可能な指摘は失敗例・修正版・採用理由・source・検出方法を一組にする。制作AI自身が受入例へ昇格させない。ユーザー受入と数学・内部QAの状態は別々に保持。

教訓を追加する前に同原因へ統合できるか確認する。小作業前に対象の規則・既知失敗・未解決修正を短いcontext packetとして取得。毎回全履歴を読ませず、参照と適用理由を残す。
