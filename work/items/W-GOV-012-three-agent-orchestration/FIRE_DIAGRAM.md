# 3agentを既存の修正／作成へ配置する火柴図

PROPOSED。これは設計図であり、実行台帳から生成した現在地や工程PASSではない。実装後はworkflow/views.pyの同じsnapshotから、既存の工程／block／capabilityの三階層へ担当を表示する。

```mermaid
flowchart TD
 U["USER：修正／作成を依頼"] --> M["M＋CODE：既存S00/S01・版と範囲を固定"]
 M --> E{"既存の入口"}
 E --> R["修正 R01〜R03：症状・原因・全影響"]
 E --> C["作成 C01〜C04：資料・既習・完全解法"]
 R --> A["A：原資料・解法・教え方を独自調査"]
 R --> B["B：表示・操作・実装制約を独自調査"]
 C --> A
 C --> B
 A --> F["M：初回所見を固定し合流"]
 B --> F
 F --> D["C05／R04：Aが穴・本文を制作"]
 F --> L["C05／R04：Bが操作・排版を制作"]
 D --> DR["B：Aの教材を非作者レビュー"]
 L --> LR["A：Bの表示を非作者レビュー"]
 DR --> K["CODE：担当・対象hash・根拠・未解決を検査"]
 LR --> K
 K --> Q{"必要な審査と根拠が揃ったか"}
 Q -->|未解決| RT["M：findingに対応する元工程へ差戻し"]
 RT -. 改訂task .-> F
 Q -->|揃った| AP["USER：C06／R05で具体案を判断"]
 AP --> IM["C07／R06：Bが実装・Mが限定統合"]
 IM --> QA["C08/C09／R07：CODE検査＋非作者の実画面審査"]
 QA --> G["G2：Mの統合もA/Bが審査"]
 G --> PUB["G3：Mが既存公開先へ反映"]
 PUB --> UV["USER：SHA一致の実アプリを評価"]
 UV --> END["R03事後/R08/L01/Z01：証拠・規則・学習可否"]
```

点線は再作業の説明で、正式実行DAGへ循環依存を追加しない。reopen／issue／改訂taskの追記で表す。承認段階の修正要求も対象の元工程へ戻す。

## node内部の受渡しと監査

```mermaid
flowchart TD
 M["M：正式nodeのclaimは一本"] --> P["CODE：版付きpacket・assignmentを検査"]
 P --> A["A：担当subtaskを実行"]
 P --> B["B：担当subtaskを実行"]
 A --> AR["Aの初回結果を固定"]
 B --> BR["Bの初回結果を固定"]
 AR --> RB["B：Aの根拠へ反証・再現"]
 BR --> RA["A：Bの根拠へ反証・再現"]
 RB --> C["M：相互所見を原結果とともに収集"]
 RA --> C
 C --> V["CODE：実task・非作者・hash・全必須scopeを検査"]
 V --> OK{"受理できるか"}
 OK -->|可| S["Mだけが同じStoreへ追記"]
 OK -->|不可| N["STALE／UNRESOLVED／BLOCKEDを保存"]
```

初回の独自調査と、設計制作後の別作者レビューは別のtask。CODEが意味の正しさを自動決定する図ではない。

## 役割交代の読み方

| 仕事 | 主作者 | 非作者の審査担当 | 主担当Mの責任 |
|---|---|---|---|
| 教材・穴・説明 | A | B | 範囲と統合の照合 |
| 三状態の表示・操作契約 | B | A | 全体の衝突確認 |
| 実装patch | B | Aが設計適合、Mが自作でない完成画面 | 限定適用と検査版固定 |
| Mが書いた統合仕様／コード | M | 関与していないA/B | 指摘を自分で免除しない |
| 全3者が寄与した同じclaim | 全員 | 有資格の非作者なし | 必須なら停止、制約を報告 |

A/Bは恒久的な専門人格ではなく役割の標準配置。roleEpochと対象claimを固定して交代する。版変更・役割変更だけでは作者履歴は消えない。
