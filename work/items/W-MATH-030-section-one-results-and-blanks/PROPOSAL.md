## 3. 共通の画面設計

### 3.1 現在の段階

表示順は次とする。

1. 既存の段階名と進行位置。
2. その空欄で使う条件・確定済みの結果。
3. 既存の導入・操作を説明する文章。
4. 計算前の式を組み立てる回答箇所。
5. 正解後、その途中式と次に必要な既存説明・計算空欄。
6. その段階で得た確定結果と、既存の次へ進む操作。

一画面に過去の全結果を積み上げない。現在の空欄に不要な参照は取り除く。新しい問題では、前の問題の係数や置換値を自動で付けない。

### 3.2 前の結果と履歴

集合には現在の空欄IDごとの参照指定があり、第1節は段階ごとの指定になっている。共通の履歴機能は第1節にも存在する。差は保存の有無ではなく、何をどこへ再表示するかの設計である。

改修後は第1節も空欄IDを参照キーにする。参照欄は条件・学習結果を区別して表示する。履歴を開くと、段階名の下にその段階の短い結論を表示し、既存の「全文を見る」を残す。導入段階には未導出の結論を付けず、元問題として記録する。

例：N01後半14では「三次0／二次−2x²／一次4x／定数−1」の四行を参照できる。N02の08では完成した2Aと−3Bの二式を参照できる。N06の10では計算中の二因子、目標の一次係数、最終の和・積を、問う内容に応じて切り替える。

### 3.3 結果が表示される条件

- 記録の式は元教材の式・正解済みの回答を参照し、別の正解文字列をUIへ手書きで重複保存しない。
- 一段階に複数の結果がある場合は、それぞれの前提設問が正解した時点で確定する。段階末の履歴概要は段階完了後に表示する。
- 空欄のない導入・説明だけの段階は、既存の進行操作で読了した後に記録する。計算結果を導いていない場合は「条件」「方針」とする。
- 誤答時は正解結果として記録しない。ヒントを見たことや選択肢を開いたことを、解決済みとみなさない。
- 過去の段階を開いても未来の記録は出さない。リセット・教材改訂時は既存の回答状態から表示条件を再判定する。
- 前提の既知結果を利用する空欄では、その結果の参照を許す。初めてその結果を導く空欄の答えを先に出すこととは区別する。

## 4. 空欄と説明の扱い

### 4.1 残すもの・変えるもの

各単元設計で指定した箇所以外の既存設問・説明は維持する。指定箇所では、完成している途中式の一部を空欄にする。新しい問題を別に追加する方式にはしない。

数学的な解法は変更しない。例えば「係数を足す」「共通のxを外へ出す」という説明は回答前に残し、その説明に沿って途中式を完成させる。直前に同じ完成解答を表示している場合は、解答部分だけを空欄化するか、具体解答を含む既存の一文を正解後に表示する。必要な理由の文章まで隠さない。

「内容を変えない」は、答えの先出しも含めて全ブロックの表示時点を固定するという意味にはしない。説明・式の意味と解く順序を保ち、既存の具体解答の表示時点だけを整える。これも本提案の明示的な設計範囲である。

### 4.2 回答の単位

- 一つの空欄は一つの変形・対応・項の選択を扱う。
- 計算前の式→係数の計算は別の判断として残す。
- 求めた答えを記録するための再入力は作らない。
- 一つの長い選択肢へ複数の判断を詰めない。NE01の最後の代入は一次因子・二次因子へ分ける。
- 選択肢は集合と同じ「選択」ボタンを使い、一列で表示。提案書内の【D01】等は設計用記号で、実際の学生画面にその番号や四角記号を出す指定ではない。
- 新規の誤答は、その段階で起きる符号・分配・因子・次数の取り違えとする。数学的に同じ値になる式を、単に見た目が異なるという理由だけで新規の誤答にしない。
- 新しい設問IDはたとえば `n01-s5-like-square-regroup` のように単元と目的を示す。各設計のD番号は設計内の参照番号であり、そのまま保存IDにしない。

## 5. 整列とスマホ改行の具体設計

### 5.1 数式の行

連続する推導を「関係記号の列」と「式の列」に分け、等号を同じ列へ揃える。最初の元式の行は関係記号を空にする。等号なしの継続行は、直前の右辺が続く位置へ字下げする。

説明文が途中にあっても、その前後で同じ基準位置を使う。説明文を数式の横の狭い欄に詰め込まない。全ての式を中央寄せするだけの整列にはしない。

空欄は現在の操作可能なボタンのまま、式の列の中に置く。KaTeXの一つの数式文字列へHTMLボタンを埋め込む設計にはしない。数式断片はそれぞれ閉じた括弧・指数として描画できる単位にし、ボタンの前後で未閉鎖の指数や分数を作らない。

### 5.2 改行の優先順位

1. 元式と変形後の式を別行にする。
2. 右辺が長い場合は、閉じた括弧や項の境界で継続行へ分ける。
3. 比較する計算は、次数や係数の対応が見える表・列へする。
4. それでも長い選択肢は、一つの選択枠の中で意味のある位置を改行する。

まず字を小さくする方法は使わない。符号と項、括弧付きのまとまり、空欄に直結する文字を可能な限り同じ行へ置く。添付画像のように末尾の `+2)` だけを中央へ落とさない。

N02の添付画像の式は、スマホでは例えば次の配置にする。

```text
  x²+2xy+y²−3x−3y+2
= x²+(2y−3)x
    +(y²−3y+2)
```

PCで右辺が収まるなら継続行をまとめてよい。320px/390px/PCで個別に実画像を確認し、収まると未検証のまま断言しない。各単元の具体的な縦配置は個別設計の第4節で指定する。

## 6. 実装へ渡すデータ設計

承認後もその場の画面幅だけから「次のページ」「結果の重要度」「空欄」を自動推測しない。以下を教材の生成元で明示する。

| データ | 内容・制約 |
|---|---|
| 問題の識別 | unit IDに加え、その単元内の例題ID。T、r,s等の名前が同じでも別問題の値は混ぜない |
| 結果の記録定義 | 記録ID、元のblock/item ID、表示を許す正解条件、段階・問題、条件／方針／結論の種類。元データから描画 |
| 空欄別の参照 | 現在のitem IDごとの必要な条件・記録ID。前段階または同じ段階で既に確定した結果だけ |
| 回答後の説明 | 具体解答が先出しになる既存ブロックに、表示を許す設問IDを明示。理由の説明は回答前に維持 |
| 数式の配置 | 元のblock・partsを参照する行定義、関係記号、継続行、対応する列。意味を持つ境界を著者が指定 |
| 設問の改訂 | 新規・移設・置換・分割・表示修正の区別と旧IDとの対応。正答の意味が変わるときは新ID |

全46回答位置の予約ID・旧ID・移行区分は [ITEM_ID_DESIGN.md](ITEM_ID_DESIGN.md) に指定した。

教える本文・式・正答の正本は既存の教材生成元。結果表示専用に別の答え集を手書きで作らない。参照用に長い既存ブロックを小さく分ける場合は、本文の文字列・式の意味・順序が変わっていないことを比較する。

`author-sequence.py`を修正し、生成JSON・監査情報を再生成する。古い差し込みパイプラインへ新しい説明を積み足す方式へ戻らない。共有UIの改修は第1節の新しいメタデータがある場合だけ適用し、集合や他の節の既存表示を変えない。

既存の保存領域名は維持する。正答の意味が変わらない設問は回答を引き継ぎ、置換・分割された新設問は未回答にする。過去の履歴を破棄せず、古い回答を新しい設問の正解として流用しない。

## 7. 検証と公開

既存の修正フローに従い、各単元内の小ブロックで元教材・設計を照合し、実画像で細部を確認してから横断確認する。新しい独自の確認手順へ置き換えない。今回は提案作成までである。

承認後の確認対象は次のとおり。

- 7単元・71段階が維持され、指定した45か所の変更が、それぞれの位置・選択肢・役割になっている。
- 記録の式・値と元教材が一致する。前提が未完了の結論や別問題の結果が出ない。
- 空欄の直前、参照欄、履歴見出しに、いま導く完成解答が漏れない。既知結果の利用は区別する。
- 移設・置換・分割した設問を二重に残さない。既存IDを別の意味で再利用しない。
- 新規の途中式と選択肢の数学的な整合性。式の整列前後で等式の意味が変わっていないこと。
- 320px・390px・PCで、未回答・正解後・誤答後の選択肢、前の結果、履歴、再読込を確認する。
- 等号位置・継続行・括弧末尾・右端欠けを実画像で確認する。横スクロール幅だけを読みやすさの証拠にしない。
- 集合・他の2テーマ・物理・練習モードの保護と回帰確認。

検証とコンパイルの後は、以前から指定されている現在の公開アプリへ直接反映し、確認用リンクを渡す。公開の確認を繰り返し求めない。ユーザーによる最終の使いやすさ・教授内容の評価を、技術試験の成功で代替しない。
