## 2. 改修案A：求めた結果を残し、必要な空欄へ引き継ぐ

### A1. 集合と同じ「現在の空欄」を基準に参照を切り替える

第1節の参照を段階単位から空欄単位へ指定できるようにする。表示内容は、元の問題・既に正解した途中結果・置換の定義など、その空欄に必要なものだけにする。

参照元は元教材のブロックを使い、別文面を手入力で複製しない。未回答の結論・現在作らせる式・後の答えを先に表示しない。問題条件として最初から与えられた式と、学習者が導いた結果は区別する。

### A2. 履歴を開いたとき、全文を開かなくても結果が分かる

「これまでの学習」の各段階に、見出しと短い確定結果を表示する。計算途中をすべて並べるのではなく、その段階で得た結果だけを元教材から参照する。結果を導かない導入段階には、無理に結果を作らない。

常時、全ページ分の結果を積み上げることはしない。現在のページには必要な結果のみ、その他の結果は履歴内に残す。従来の「全文を見る」も維持する。

### A3. 全7単元の確認対象

| 単元 | 引き継ぐ主な結果 |
|---|---|
| N01 | 次数別の整理結果→式全体の組立て→整理後の次数。前半の例と後半の例を混同しない |
| N02 | A・Bの定義、−B、2A、−3B、2A−3B。完成済みの二式を足す段階で両方を見られるようにする |
| N03 | 指数法則が必要な場合の参照、分配先の元の式、一行目・二行目の積→同類項の整理 |
| N04 | 導いた公式、公式へ対応させるまとまり、二組の積、Tの定義→展開→元の文字への復元 |
| N05 | 共通因数、展開して得た係数の関係、候補を判定する条件→比較→因数分解 |

前ページの結論をすべて機械的に次ページへ出すのではなく、「この空欄を解くために使う結果」を結び付ける。

## 3. 改修案B：既存の途中式を学習者が組み立てる

計算空欄は必要なものを残す。その前にある「どの項をまとめるか」「何を共通にするか」「何を代入するか」を、式の一部分として答える機会を増やす。理由の文章や計算の並びは保持する。

以下の【空欄】は提案書用の表記。実装では集合と同じ「選択」ボタンを使用する。各行は配置候補であり、そのまま14個の回答操作を純増させる指定ではない。既存の式変形空欄と重なる場合は統合し、既存の回答をもう一度選ばせない。

| 単元 | 既存の推導内で参加させる箇所① | 箇所②・既存空欄の改善 |
|---|---|---|
| N01 | `5x³y=(【空欄】)y¹`：yを残し、係数側のまとまりを作る | `3x²−5x²=(【空欄】)x²`：数値−2の前に、係数の差3−5を作る |
| N02 | `A+B=【三次の係数の式】x³+…`：計算前の2−1を作る | `A−B=A+【空欄】`：完成済みの−Bを使う形へ変える。後の係数計算と分ける |
| N03 | 既存の「二項×三項を二行へ分ける」空欄の前から、同値の完成解答の先出しをなくす | 六つの積から二次の項・一次の項を集める中間式を答える。既存の−5x²・16xを答える操作と役割を分ける |
| N04 | `(3x−2)(3x+2)=【空欄】`：計算前の平方の差を作る | `(a+b+c)²=(【空欄】+c)²`：T=a+bを使ってまとまりを置き換える |
| N05 | 展開した交差項 `psx+qrx=(【空欄】)x`：一次係数ps+qrを作る | 係数比較で「どの式が7に等しいか」を答える。すでにある7を選ぶ空欄と統合し、同じ条件を二度答えさせない |
| N06 | `x²+(3xy−x)+(2y²−3y−2)` の括弧部分を作る：注目する文字xで分類する | `x²+((【空欄】)+(y−2))x+(2y+1)(y−2)`：求めた二因子を和・積へ対応させる。最後の因数分解とは役割を分ける |
| NE01 | 一般の三乗の展開で、a²bを含む二項を集める段階を答える。係数3の計算だけにしない | 既存の `a³+b³=(a+b)((a+b)²−3ab)` を作る空欄を保ち、共通因数と括弧の中を段階的に完成させる。既存の一括回答は重複させない |

### 空欄の作り方

- 一つの空欄で一つの判断を扱う。複数の係数や式変形を長い選択肢に詰め込まない。
- 「公式名はどれか」だけを増やさず、途中式の構造を実際に完成させる。
- 元の説明が方法を教えていることは維持する。ただし同じ完成解答が直前に表示される箇所は、元の式の該当部分を回答箇所に変え、正解後に元の完成形として読めるようにする。
- 選択肢は一列に置く。符号の扱い、分配先、共通因数、和と積の対応など、その段階で起こる誤りを使う。
- 正解した式は以後の推導と履歴へそのまま引き継ぐ。記録用に同じ答えを再入力させない。
- 空欄数や割合を目標にしない。既存の推導空欄の改善と、まだ参加できない要所への追加を優先する。

## 4. 追加提案：推導式の整列と改行

添付画像では、長い等式を横に並べた結果、右辺の定数項 `+2)` だけが次の行の中央へ移動している。上の単独式と下の等式では開始位置も異なり、変形の対応が追いにくい。画面全体の確認ではなく、この画像から確認できる問題である。

- 長い変形は一行に押し込まず、元の式と変形後の式を別行にし、行頭の等号を揃える。
- 説明文を挟む場合は、数式を巨大な一つの枠に統合せず、式の開始位置・字下げを共通にする。式と説明の順序を保持する。
- 同類項を比較する表・縦の計算では、対応する次数の列を揃える。すべての式に一律で表を使わない。
- 括弧でくくったまとまり、符号とその項、空欄と直結する文字は、可能な限り一緒に扱う。画像のように `+2)` だけを次行の中央へ出さない。
- スマホで一行が収まらない場合は、式全体を小さくする前に、等号・加減号など意味のある境界で改行する。括弧内も長い場合は継続行を字下げし、対応が追える形にする。幅ごとの実画面で決める。
- 回答前の選択ボタンと正解後の式の両方で、行の揃い方・右端の欠けを確認する。

画像の等式は、本文を変えず、次の表示を基本案とする。

```latex
\begin{aligned}
&x^2+2xy+y^2-3x-3y+2\\
&=x^2+(2y-3)x+(y^2-3y+2)
\end{aligned}
```

これは十分な幅があるときの基本形。320pxでも右辺が収まると未検証のまま断言せず、狭い画面では意味のある項の境界で追加改行する。同じ問題内の式には共通の基準位置を使う。

## 5. 作業範囲・確認方法

実装対象は、この第1節の参照・結果表示データ、既存式内の空欄、推導式の整列・改行、必要な表示処理に限定する。集合の内容・挙動、他の節、本文の説明順序は維持する。教材の生成元を修正して再生成し、生成JSONだけを手修正しない。

確認は次を中心に行う。

1. 7単元の段階間の依存を全件確認し、現在の空欄に必要な前提・結果だけが表示されること。
2. 履歴の結果が教材の実際の確定結果と一致し、未完了の結果や別問題の答えを表示しないこと。
3. 空欄にした途中式の答えが、回答前の直前本文・参照欄・履歴見出しから漏れないこと。
4. 式変形の選択肢が数学的にも設問上も判定でき、同じ答えを求める操作が重複しないこと。
5. スマホ320/390pxとPCで、参照→途中式の回答→次段階→履歴→再読込を通して確認すること。
6. 既存の回答を保持し、新規・置換された設問だけを未回答として扱うこと。別の意味の設問へ既存IDを使い回さないこと。
7. 同じ推導の行頭・等号・継続行の字下げを確認する。320/390pxで、括弧の末尾だけの孤立や、空欄回答前後の欠けがないこと。

提案段階ではアプリのコード・教材・公開版は変更していない。承認後はこの第1節だけを改修し、検証・コンパイル後、既に指定された公開アプリへ反映する。
